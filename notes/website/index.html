~/website

A few notes about why this portfolio exists, how the Notes section came to be, and the little Easter egg hidden inside.

How it started

The original idea was actually quite simple. I wanted somewhere to explain my projects in more detail than a CV could, while keeping everything in one place instead of scattering it across different platforms.

The first version of the website was just the portfolio page you see at chy-sabrina.github.io. There was not supposed to be a Notes section at all.

Why I added Notes

As I started writing about my projects, I realized there were many things that never made it onto the portfolio itself.

Small design decisions, unexpected bugs, ideas that did not work, and lessons learnt along the way were all part of the project, but they did not really belong on the main page.

That is how the Notes section came about. Instead of only showing the final result, it gives me a place to document some of the process behind it.

It is also intentionally a little less formal. Think of it as the part of the website where I can write down the things I would normally tell someone if they asked, "So... how did you actually build this?"

The hidden page

You might have noticed that this page is not immediately accessible.

I wanted these notes to be discoverable, but not something every visitor would stumble upon by accident. They are a bit more personal than the main portfolio, so hiding them behind a small challenge felt more interesting than simply adding another navigation link.

The inspiration

The idea for the Easter egg actually came from my internship at AIA.

While reading a penetration testing report, I came across a classic broken authorization vulnerability. A low-privilege user could simply change a parameter such as role=guest to role=admin and suddenly gain access to functionality they were never supposed to see.

I thought it would be fun to turn that into a harmless Easter egg. My first idea was to let every visitor arrive as a "guest" and have them discover they could change their role to "admin" through Developer Tools to unlock the Notes section.

After thinking about it a bit more, I realized it was probably too obscure. Even if someone noticed the word "guest", most people would never think to edit it.

So I explored another idea instead: hiding the Notes page completely and letting people discover it through forced browsing. That felt closer to the security theme, but it still had the same problem—it was almost impossible to find unless someone happened to browse the GitHub repository.

The current version is a compromise between the two. The Notes page is visible, but opening it requires finding the access code hidden in the page source and entering it into the fake terminal. It is not meant to be secure—quite the opposite. It is simply a small nod to the kinds of security concepts that inspired it, and a little reward for anyone curious enough to press F12 and explore.
