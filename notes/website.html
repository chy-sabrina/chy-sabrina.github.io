~/website

A few notes about why this portfolio exists, how the Notes section came to be, and the little Easter egg hidden inside.

How it started

The original idea was actually quite simple. I wanted somewhere to explain my projects in more detail than a CV could, while keeping everything in one place instead of scattering it across different platforms.

The first version of the website was just the portfolio page you see at chy-sabrina.github.io. There was not supposed to be a Notes section at all.

Why I added Notes

As I started writing about my projects, I realised there were many things that never made it onto the portfolio itself.

Small design decisions, unexpected bugs, ideas that did not work, and lessons learnt along the way were all part of the project, but they did not really belong on the main page.

That is how the Notes section came about. Instead of only showing the final result, it gives me a place to document some of the process behind it.

It is also intentionally a little less formal. Think of it as the part of the website where I can write down the things I would normally tell someone if they asked, "So... how did you actually build this?"

The hidden page

You might have noticed that this page is not immediately accessible.

I wanted these notes to be discoverable, but not something every visitor would stumble upon by accident. They are a bit more personal than the main portfolio, so hiding them behind a small challenge felt more interesting than simply adding another navigation link.

The inspiration

The idea actually came from my internship at AIA.

While reading a penetration testing report, I came across a classic broken authorization vulnerability. A low-privilege user could simply change a parameter like user_id to an administrator's value and suddenly gain access to functionality they should not have been able to reach.

It was one of those examples that seems almost too simple, yet has caused countless real-world security issues.

That eventually became the inspiration for the access mechanism used here. Every visitor starts as a "guest", and the hidden section is unlocked by becoming "admin"—a harmless little reference to an authorization flaw instead of an actual vulnerability.

Designing the puzzle

I considered a few different ideas before settling on the current one.

My first thought was to leave the page completely unlinked and rely on forced browsing. The problem was that almost nobody would ever discover it unless they happened to browse the GitHub repository.

I also thought about making visitors edit the page directly through Developer Tools, but that felt more like a trick than a puzzle.

The current version is a compromise between the two. The Notes page is visible in the navigation bar, but opening it requires finding the access code hidden in the page source and entering it into the fake terminal.

It is not meant to be secure—if anything, it is the opposite. It is simply a small Easter egg for anyone curious enough to press F12 and have a look around.
